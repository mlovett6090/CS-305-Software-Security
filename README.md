# CS-305-Software-Security
“Security-focused software project demonstrating vulnerability assessment, secure coding practices, and HTTPS implementation for Artemis Financial.”
Portfolio Reflection (Project One)

Who was the client, and what issue did they want addressed? What did I do well, and why is secure coding important? Which part of the vulnerability assessment was challenging or helpful? Artemis Financial is a financial consulting company that provides services such as savings, retirement, and investment planning. The company required a vulnerability assessment of its Spring Boot REST application to identify security weaknesses and risks to sensitive financial data. The main issue was determining where the application was vulnerable, including areas such as input validation, authentication, error handling, and outdated dependencies. I did well in conducting both a manual code review and automated scanning using OWASP Dependency-Check to identify vulnerabilities such as hardcoded credentials, lack of HTTPS enforcement, and outdated libraries like Spring, Tomcat, and Jackson. Secure coding is important because it protects the confidentiality, integrity, and availability of data, which is critical in financial systems. Software security adds value by reducing risk, maintaining customer trust, and preventing costly breaches. One of the most challenging yet helpful parts of the assessment was interpreting the dependency-check results and distinguishing between true vulnerabilities and false positives.

How did I increase layers of security, and how will I assess vulnerabilities in the future? How did I ensure the software remained functional and secure? What tools and practices did I use, and what can I show employers? Although Project One focused primarily on identifying vulnerabilities, I recommended increasing layers of security by implementing HTTPS, removing hardcoded credentials, improving input validation, and updating vulnerable dependencies. In the future, I would use a combination of tools such as OWASP Dependency-Check, static analysis (SAST), and dynamic testing (DAST) to assess vulnerabilities and determine mitigation strategies. I ensured accuracy in my assessment by carefully reviewing the code and validating findings with automated scans, even though code refactoring was not the primary focus of this project. The tools and practices I used—such as OWASP Dependency-Check, Maven, and secure coding principles—will be valuable in future assignments and professional work. From this assignment, I can show employers my ability to conduct vulnerability assessments, analyze security risks, and apply industry-standard tools to evaluate the security of real-world applications.
